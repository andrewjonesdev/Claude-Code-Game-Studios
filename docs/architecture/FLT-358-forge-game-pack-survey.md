## 1. Summary and recommendation

Build the first engine adapter on **Epic's UE 5.8 Unreal MCP plugin**, identifier `ModelContextProtocol`, only after an authenticated live smoke test on an idle PC and the WT-3796 producer-contract gate. Keep the Forge host, pack loader, dependency policy, security policy and UAT machinery shared with the other packs. CCGS supplies Game pack content and Unreal-specific adapters. Forge remains one C# product. Read-only Phase-0 work may start now; do not open build tickets while FLT-347/351/350/354 remain unbuilt.

Epic's [official 5.8 MCP documentation](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor?application_version=5.8) confirms an Experimental local HTTP integration, extensible toolsets and serialized game-thread execution. This gives Forge a protocol boundary independent of the user's IDE. Enable only the toolsets needed for the probe; discover actual tools before selecting operations. A custom IDE fork is unnecessary for this first slice.

Use UnrealSharp as the gameplay-language adapter inside the Game pack. Use original C++ for engine-facing extensions and C#/.NET 10 for Forge tooling and gameplay. The fixed gameplay stack is GMCv2 + GMAS + Narrative Pro; do not substitute GAS. The commercial stack belongs in an entitlement-gated overlay. BpGenerator is excised from the active provider set until a human supplies written AI-use entitlement; no bridge start, schema read or AI probe is allowed before that. Rider and Visual Studio remain possible debugging tools. Workspace generation supports VS Code, Cursor and Antigravity without making any one IDE the control plane.

The engine boundary is per-engine. Implement only Unreal now. Unity is far-future work.

## 3. Pack architecture

### Ownership and content

Forge core owns scheduling, run identity, dependency decisions, authorization, evidence storage, UAT evaluation and review routing. The Game pack registers content and adapters against those contracts. It does not implement parallel copies of core services.

Use three assemblies: `Forge.Game.Unreal → Forge.Game.Abstractions → Forge.Core`. Core owns MCP transport, canonical `tools/list` + schema SHA-256 digest, untrusted-output wrapping, quarantine and policy/review routing. Abstractions defines engine/language observations; Unreal implements them without duplicating Core services. The Unreal adapter descriptor is **Win64-only**. It runs inside the authenticated gaming-PC daemon, reached over mTLS or SSH with run-bound, expiring, non-replayable tokens; no exposed remote editor port.

### Adapters inside the pack

- **UnrealEngineAdapter (C#):** resolves an editor-less project target, opens authorized editor sessions and delegates through Core. Build/package jobs use the target without an editor. The daemon enforces workspace ownership.
- **EpicMcpProvider (C#):** Unreal-specific tool mapping and observations only, using Core's pinned [MCP C# SDK](https://github.com/modelcontextprotocol/csharp-sdk) integration, transport and digest. Never introduce a second MCP client, schema cache or authorization path.
- **UnrealBuildProvider (C#):** invokes `dotnet.exe` with installed `UnrealBuildTool.dll` / `AutomationTool.dll` directly; no `.bat` or `cmd.exe`. Section 4 defines process and path controls.
- **UnrealSharpAdapter (C#):** uses the pinned generation/reload pipeline; reads the single engine-adapter packaged smoke artifact rather than performing another cook. Original C++ wrappers call public APIs only, with Engine-source match rejection and a file-by-file licence receipt.
- **Workspace/debug adapters (C#):** generate local IDE recipes and record attach capabilities; forks use netcoredbg. BpGenerator has no active registration, imported implementation or bridge until written human entitlement and listener controls both pass. Disabling a Forge provider alone is insufficient: disable the uproject plugin too.

### Engine-adapter interface sketch

Proposed signatures only; these are **not existing Forge APIs**. All parameter/result types below are placeholders to bind to WT-3796's actual contracts. An `AuthorizedOperation` must be issued/validated by core policy; it is never an unchecked caller-supplied approval flag.

```csharp
public interface IEngineAdapter
{
    string EngineId { get; }
    Task<ProjectTarget> ResolveTargetAsync(ProjectContext project, CancellationToken ct);
    Task<IEditorSession> OpenEditorSessionAsync(
        ProjectTarget target, AuthorizedSessionOpen request, CancellationToken ct);
    Task<BuildObservation> BuildAsync(
        ProjectTarget target, AuthorizedBuild request, CancellationToken ct);
    Task<PackagedSmokeObservation> PackageOrAutomateAsync(
        ProjectTarget target, AuthorizedAutomation request, CancellationToken ct);
}

public interface IEditorSession : IAsyncDisposable
{
    Task<CapabilityCatalog> DiscoverAsync(AuthorizedDiscovery request, CancellationToken ct);
    Task<OperationObservation> ExecuteAsync(AuthorizedOperation operation, CancellationToken ct);
    Task<SurfaceEvidence> CaptureSurfaceAsync(AuthorizedSurfaceCapture request, CancellationToken ct);
    Task<CleanupObservation> CloseAsync(CancellationToken ct);
}

public interface IGameplayLanguageAdapter
{
    string LanguageId { get; }
    Task<BindingObservation> GenerateBindingsAsync(
        ProjectTarget target, AuthorizedBindingRequest request, CancellationToken ct);
    Task<ReloadObservation> CheckReloadAsync(
        IEditorSession session, AuthorizedReloadProbe request, CancellationToken ct);
    Task<RuntimeObservation> InspectPackagedSmokeAsync(
        ProjectTarget target, PackagedSmokeObservation smoke, CancellationToken ct);
}
```

`ProjectContext` identifies an authorized workspace and target machine. `ProjectTarget` pins that workspace, project and engine without requiring an editor PID. Bindings/build/package operate on the target; packaged checks require Editor closed. `OpenEditorSessionAsync` is the only live-session factory; `CloseAsync` and `DisposeAsync` share idempotent teardown. The receipt goes to Core even on cancellation/crash, using bounded cleanup independent of the cancelled request. A capability describes provider, input schema, effects and availability. Unsupported capabilities return an explicit unavailable observation. No fabricated success or implicit provider fallback.

Serialize operations through a session queue (a logical target session for editor-less jobs). Total lock order for every path: **session queue → workspace lease → heavy-job semaphore**; release in reverse order, never acquire backwards. Schema changes invalidate prior capability authorization. Treat tool output as untrusted data, not instructions. A timed-out mutation has an unknown outcome until state is inspected; do not blindly retry. On cancellation, record child-process/editor state and cleanup outcome. Evidence capture must also obey path/data policy.

### Identity, authorization and listener lifecycle

- Install key = machine GUID + engine build/CL (`5.8.3 / 58210709`) + content hash. Session key = install key + project id + random session id + spawned Editor PID + process start time. Reject RogueRoyale: canonical `-Project` must match the disposable probe target and differ from RogueRoyale.
- Core's protected execution-authorization digest binds session id, `providerId`, `toolName`, `capability`, `opId`, `attemptId`, SHA-256 of canonical `tools/list` and schemas, SHA-256(args) for the exact execution inputs, expiry and a single-use nonce. Validate every binding immediately before dispatch under the current lease; changing provider/tool/capability/op/attempt invalidates approval. Keep the execution digest inside the protected authorization path; evidence stores only allow-list-redacted arguments canonicalized **after** redaction, with their separate evidence digest. Secret-bearing input changes invalidate approval without persisting raw secrets. Invalidate on identity/schema change. Daemon credentials and listener bearer tokens never enter project YAML or evidence.
- Keep an op-id across transport retries. Core appends intent → result → inspection records; never overwrite history. Outcomes are `succeeded`, `failed`, `unknown`, `unavailable`. Timeout/cancel after dispatch is `unknown`, not a fabricated failure/success; single-use approval cannot execute twice. Inspect/reconcile the original op-id before any new authorization, never blindly resubmit.
- Before opening Editor, require `BpGeneratorUltimate` disabled in the probe uproject and refuse the session if **any listener on :9877** is open. Do not kill an unrelated process. Keep autostart/auto-connect off. Bind MCP to an ephemeral `127.0.0.1:<port>` with a per-session bearer token, exact Host validation and an explicit Origin allow-list (reject unapproved browser origins). Never use default :8000 as identity.
- Enumerate **AF_INET and AF_INET6** with `GetExtendedTcpTable` or `Get-NetTCPConnection`. ALL LISTEN entries on the chosen port must belong to spawned `EditorPid`, with recorded start time and exact probe `-Project`; each `LocalAddress` must be exactly `127.0.0.1` or `::1`. Reject wildcard `0.0.0.0` / `[::]` and every other address or owner, even alongside a valid entry. Probe chosen port, :8000 and :9877 before Editor start **and after start**, before handshake and calls; unexpected listeners or spoofed/reused PID/port fail closed. If installed Epic 5.8.3 cannot enforce bearer + Host/Origin, HTTP does not start. A stdio/local-proxy fallback requires verified enforcement and an authenticated/private editor-side channel; a proxy in front of an unauthenticated TCP listener is insufficient.
- `CloseAsync`/disposal stops the actual editor-side server, closes transport and reaps owned processes. Teardown receipt lists PID/start-time, port, stop result and observed absence of owned listeners/processes. Failure quarantines the target; provider unregister alone never counts as cleanup. No port forwarding or firewall exception substitutes for auth.

### Workspace fencing and bounded input

Core grants a workspace reader/writer lease with attempt fencing: holder heartbeats every 5 seconds; 30 seconds without a valid heartbeat, measured by the executor's monotonic clock, expires the lease. Reads share only a stable revision; build, cook, editor mutation, binding generation and reload require exclusive access plus the executor's heavy-job semaphore, always in the total lock order above. Quiesce UnrealSharp's watcher during exclusive jobs; auto-reload requires the same lease and explicit authorization. Per-session serialization alone is insufficient.

Timeout/cancellation, lease expiry or holder/executor crash sets durable `NeedsReconciliation` before releasing/regranting control; recovery treats any orphaned in-flight intent as fenced. Revoke the old attempt; stop owned children where possible and record uncertain editor actions. While fenced, block **readers, ordinary dispatch and publication**, including builds/reloads. Only Core's reconciliation coordinator, under a fresh attempt and exclusive lease in the same lock order, may run explicitly authorized inspection/teardown and clear the fence after proving stable editor/process/workspace state, completing cleanup and closing the prior `opId` with append-only inspection evidence. A client timeout does not stop a game-thread action. Stale holders cannot publish or clear the fence. Any subsequent execution requires a new authorization digest binding current `providerId`, `toolName`, `capability`, `opId` and `attemptId`.

Initial local ceilings: 1 MiB per discovery response, 4 MiB total expanded schemas, JSON depth 32, 256 tools, 128 parameters per tool, 1,024 visited expansion nodes and 10 seconds discovery time. MCP `tools/call` responses have a 4 MiB aggregate decoded-byte cap across all content (including streamed/decompressed data), JSON depth 32 and 30-second wall-clock deadline from dispatch to complete response; enforce while receiving, before unbounded buffering/parsing. Core may tighten these. Use `TypeNameHandling.None` where Newtonsoft.Json is used; no polymorphic type materialization. Allow-list meta-tool expansion with a visited set; discovery caps/cycles yield **incomplete**, never a complete catalogue, and block dispatch until required schemas are complete. A capped call never yields success or publishable partial evidence; a dispatched mutation becomes `unknown` and fenced for reconciliation. Redact by allow-list before canonicalizing/storing args/log excerpts in evidence; raw-log digests reference a separate access-controlled store, never inline raw logs or secrets in evidence.

Future validator tests cover lease races, watcher/build conflicts, stale discovery/attempts, spoofed ports, duplicate op-id submission, Job Object cleanup and cancel-never-succeeds. Parsing tests include cyclic/oversized/fuzzed input and a secret-shaped negative case proving no secret in canonical evidence. These are planned checks, not fixtures or payloads written in this survey.
